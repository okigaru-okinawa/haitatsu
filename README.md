# 配達ルートアプリ（引き継ぎメモ）

妻の薬局配達用。iPhoneのSafariで使うWebアプリ。午前約28件・午後約20件、西原の営業所発着、高速なし。
公開先：GitHub Pages（このリポジトリの main / root）。合言葉・APIキー・個人名はリポジトリに入れない。

## 構成
- `index.html` … アプリ本体（1ファイル）。地図だけ Leaflet + OpenStreetMap を使う時に読み込む
- `index_1.html` … 旧アドレスからの転送用
- `manifest.json`, `icon-*.png` … ホーム画面追加用
- `apps-script/Code.gs` … スプレッドシート `haitatsu_data` に紐づく Apps Script の控え。**ここを直しても自動では反映されない**（Apps Script の画面に貼って「デプロイを管理 → 編集 → 新バージョン」が必要）
  - スクリプトプロパティ：`API_KEY`（Routes API + Geocoding API のみに制限）、`TOKEN`
  - doGet `?a=master` 薬局マスタ取得 / doPost `routes`（computeRoutes の代理。`mask` で返す項目を指定可）`log` `note` `visit` `add`

## データ（スプレッドシート）
- 薬局マスタ：薬局ID, 名前, フリガナ, 住所, 電話, 緯度, 経度, 駐車_緯度, 駐車_経度, タグ, 備考, 訪問回数, 平均滞在分, 最終訪問日, 追加元
  - 厚労省 医療情報ネット オープンデータ(2026-06-01) 479件 ＋ 九州厚生局 保険薬局指定一覧(2026-10-01) で不足98件を追加（ID先頭K）。手入力はID先頭U
- 便の記録：便ID, 日付, 便, 出発時刻, 帰着時刻, 件数, 予測終了, 実際終了, 予測距離km, ルート変更回数
- 配達記録：便ID, 日付, 薬局ID, 薬局名, 予定順, 実際順, 予測到着(出発時点の予測), 完了時刻, 滞在分, 状態, 午前必着(現状は「優先」フラグ)
- 変更の記録：便ID, 日時, 種類, 対象薬局ID, 緯度, 経度
- 記録は端末に貯めて裏で送信（失敗時は再送）

## アプリの動き（v4）
- 画面：下タブ（登録／配達／振り返り／設定）。青い「案内標識」パネルに、いま一番大事なこと（次の配達先・終わる予定）を出す
- 登録：午前/午後、検索（名前・フリガナ・電話。「、」や空白区切りで複数同時）。行は左スワイプで削除（元に戻せる）、長押しで並べ替え、旗で「最初に行く」
  - 「最短ルートを作る」＝順番を最適化 ／ 「この順番で行く」＝並べた順のまま時間だけ計算（trip.manual = true）
- ルート：computeRoutes + optimizeWaypointOrder（TRAFFIC_AWARE、高速・有料回避）。25件超は直線距離の巡回順で等分して複数回呼ぶ。順番固定は routeFixed
- 出発前：終わる予定・件数・道のり、全体マップ、路線図ふうの一覧（長押しで入れ替え、スワイプで外す）
- 配達中：下の大きいボタンは状態で変わる（ナビ前＝ナビ開始 ／ ナビ後＝配達完了・次へ）。完了直後は「まだだった」で戻せる
- ルート変更：現在地から組み直す／先に行く／追加／今日は行かない／後回し／このあとの並べ替え。通信できない時は順番だけ変更
- 自動完了：Googleマップから戻った時、行き先の250m以内なら完了。営業所の250m以内なら便を終了
- 滞在時間：到着（ナビ開始＋区間の所要、ただし戻った時刻まで）から、次の「ナビ開始」を押すまで。記録はその時に確定して送る
- 便を終えると day.history に移り、同じ枠で次の便を登録できる。日付が変わると前の日は prevDay に残る
- 振り返り：便ごとの予測と実際、薬局ごとのタグ・備考・駐車位置（次回の配達画面に出る）
- 設定の引き継ぎ：アドレスの `#setup=<base64(JSON{u,t,d})>`。ホーム画面のアプリは保存場所が別なので、設定リンクの貼り付けでも移せる
- `vendor/` … Leaflet（地図）と SortableJS（長押し並べ替え）を同梱
